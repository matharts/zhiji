# 知几功能需求与公理设计分析

以桌面应用 `ffead35` 为重构前样本。在包含草稿保存和重新打开的核心工作流中，**设计矩阵不是下三角矩阵，重排行列也不能把这组六个 FR 和 DP 排成对角非零的下三角矩阵**。在同一工作区内，固定偏好、完成临时编辑，只看取数、排盘、看盘、标注和输出图片时，矩阵可以按这五项排成下三角。草稿读取与工作区恢复分开后的矩阵见[重构后的设计矩阵](#重构后的设计矩阵)。

## 公理一 · 保持功能需求独立

设计方程写作 `{FR} = [A]{DP}`。行是功能需求，列是设计参数。这里用 `X` 表示该 DP 对该 FR 所要求的输出有直接作用，`0` 表示在本分析的边界内没有直接作用。经中间状态传递的影响只在直接接口上记一次。对角矩阵允许独立设置每个 DP。对角非零的下三角矩阵允许按从上到下的顺序设置 DP，后设的参数不会破坏前面已满足的 FR。该顺序描述设计参数之间的关系，用户仍可按工作需要自由选择操作顺序。[Suh，MIT 2.882，第 1 章 §1.5–1.6](https://web.mit.edu/2.882/www/chapter1/chapter1.htm)

|  | DP1 取数 | DP2 排盘 | DP3 呈现 | DP4 标注 | DP5 草稿 | DP6 图片 |
| --- | :---: | :---: | :---: | :---: | :---: | :---: |
| **FR1 取得参数** | X | 0 | 0 | 0 | 0 | 0 |
| **FR2 建立命盘** | X | X | 0 | 0 | **X** | 0 |
| **FR3 查看盘面** | 0 | X | X | 0 | **X** | 0 |
| **FR4 记录分析** | 0 | 0 | X | X | **X** | 0 |
| **FR5 草稿续编** | 0 | X | X | X | X | 0 |
| **FR6 分享图片** | 0 | X | X | X | 0 | X |

- **取数、排盘、呈现按结果向下游传递。** 已确认的日期参数进入排盘会话（`A21`），呈现读取计算结果（`A32`）。普通显示过滤直接更改 `Display`。位星开关会改计算输入并触发重算，已计入 DP2 的范围。[日期应用](../../src/session/mod.rs#L81)、[盘面绘制绑定](../../src/workspace/view/chart_workspace.rs#L115)、[两类显示开关](../../src/session/mod.rs#L245)
- **标注位置和图片由同一盘面基准派生。** 标注层和盘面共用局部坐标与缩放（`A43`）。图片从当前命盘、显示及配色和当前组的可见标注构建（`A62`、`A63`、`A64`），发起后使用冻结的内容绘制。[标注手势](../../src/workspace/view/chart_workspace.rs#L202)、[共同缩放](../../src/workspace/view/chart_workspace.rs#L324)、[图片快照](../../src/workspace/mod.rs#L312)
- **草稿保存与恢复形成双向作用。** 保存读取生效的 `Input` 和飞宫、显示配置和配色、全部标注及批注（`A52`、`A53`、`A54`）。打开后，恢复策略将草稿的这些值写回当前工作区，重新建立可见命盘与可编辑标注（`A25`、`A35`、`A45`）。例如，变更排盘参数会改写下一次保存的内容，打开另一份合法草稿又会改掉当前命盘。这两条都是该入口的实际功能。[草稿快照字段](https://github.com/matharts/zhiji/blob/ffead35b29a84b6d55fc48273b3834850624fd5c/src/workspace/snapshot.rs#L105)、[校验后重建会话](https://github.com/matharts/zhiji/blob/ffead35b29a84b6d55fc48273b3834850624fd5c/src/workspace/snapshot.rs#L63)、[安装草稿到工作区](https://github.com/matharts/zhiji/blob/ffead35b29a84b6d55fc48273b3834850624fd5c/src/workspace/mod.rs#L531)

**为什么换顺序也不行。** 排盘与草稿对应的 `A25` 和 `A52` 都非零。保持 FR/DP 配对时，把排盘放前面，恢复写入落在对角线上方。把草稿放前面，保存读取落在对角线上方。即使允许分别排列行和列，一个对角非零的下三角矩阵首行也必须恰好有一个 `X`。唯一候选是 FR1 与 DP1。移除这一行一列后，剩下各行仍至少有两个 `X`，无法得到下一行。[Suh 与 Do，Design Matrix Interpretation and Manipulation](https://patents.google.com/patent/US7546577B2/en)

**为什么单次工作流可以是下三角。** 以已打开的工作区为起点，只涉及取数、排盘、呈现、标注、图片五项时，取上述矩阵的 `1、2、3、4、6` 行和列，对角线上方全为 `0`。这是在已提交编辑的条件下得到的结果。把临时编辑也纳入分析时，图片入口本身会提交文字，导出还结束颜色编辑，因而会对在编状态产生额外作用。[导出和复制入口](../../src/workspace/mod.rs#L323)

### 下钻 · 同一个命宫的两种输入

若把「用月份和时辰决定当前命宫」与「直接指定当前命宫」当成两条应独立保持的 FR，二者构成满 `X` 的 `2×2` 子矩阵。

|  | 月份和时辰的联动策略 | 直接指定命宫的联动策略 |
| --- | :---: | :---: |
| 月时决定的命宫作为当前结果 | X | X |
| 手动指定的命宫作为当前结果 | X | X |

直接指定命宫会清空月、时。再把月、时都选上，就会用推算结果覆盖当前命宫。只填一项时，保留当前命宫。这两种方式在产品里表达的是同一条需求，即以用户选择的来源确定当前命宫。命宫变化后，大限跟随默认值，是这个结果继续向下游生效。[月时联动与手动指定](../../src/session/mod.rs#L229)、[月时齐全才更新](../../src/session/mod.rs#L283)、[大限跟随](../../src/session/mod.rs#L51)

## 公理二 · 最小化信息量

信息量由满足已设定功能要求的成功概率决定，`I = −log₂(p)`。目前材料能确认需求、状态读写和部分验收条件，缺少可比较设计在相同条件下的成功概率。这里能判定矩阵结构，信息量尚无法量化。例如，比较两种草稿方案时，可以先约定「合法草稿保存后恢复等价状态」「无效草稿保留当前工作」的判定条件，再给出场景分布和实测成功率。[Suh，MIT 2.882，第 1 章 §1.7.8](https://web.mit.edu/2.882/www/chapter1/chapter1.htm)

## 重构后的设计矩阵

读取结果是已校验的文档内容以及原始文件身份。未保存保护通过后，工作区用这些数据重建排盘会话并一次性安装显示、配色和标注。应用层随后用实际安装的内容建立干净基线。保存和导图各自以冻结快照为输入，发起操作前结束临时编辑的职责仍在工作区。[文件读取](../../src/draft/file.rs#L179)、[工作区恢复](../../src/workspace/mod.rs#L532)、[打开结果提交](../../src/app/files.rs#L319)

固定 `.ziwei` v4 格式与领域校验规则，在临时编辑已提交的条件下，按这一层的结果建模。草稿续编依次经过读取校验、排盘及显示和标注恢复。文件写入作为独立的下游能力。

| 功能需求 | 日期取数 | 读取校验 | 排盘会话 | 盘面呈现 | 标注分组 | 草稿写入 | 图片输出 |
| --- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| 取得日期排盘参数 | X | 0 | 0 | 0 | 0 | 0 | 0 |
| 从文件取得有效草稿内容 | 0 | X | 0 | 0 | 0 | 0 | 0 |

| 按选择查看盘面及恢复草稿显示 | 0 | X | X | X | 0 | 0 | 0 |
| 编辑、查看或恢复盘面标注 | 0 | X | 0 | X | X | 0 | 0 |
| 保存完整草稿 | 0 | 0 | X | X | X | X | 0 |

这组 FR 与 DP 的矩阵是下三角。读取和写入共同遵守格式契约，将来变更格式时需同时核对两侧。文件冲突、未保存确认和临时编辑提交仍由应用协调。

| FR9 保存和恢复跨启动偏好 | X | X |

- **`A4,9`。** 应用偏好会直接写入活动 `Session` 的配色。开启显示记忆时还恢复保存的显示开关，关闭时应用默认开关。这里取 FR4 的盘面配色及显示结果，排盘计算保持独立。[应用偏好](../../src/app/state.rs#L313)、[设置会话配色](../../src/workspace/mod.rs#L273)、[纯显示与配色写入](../../src/session/mod.rs#L138)
- **`A9,4`。** 设置快照从当前 `Session` 读取配色。草稿恢复也会替换同一个值。假设 `settings.json` 可正常写入，打开配色与先前已提交值不同的草稿后，只要设置轮询发现颜色编辑器已关闭、配色发生变化，就会自动提交偏好写入。显示选项也会在形成偏好快照时一并记录。仅修改显示开关不会触发这条配色自动写入条件。[恢复草稿](../../src/workspace/mod.rs#L531)、[设置快照字段](../../src/app/state.rs#L344)、[配色自动写入判定](../../src/app/state.rs#L673)

在 macOS 上，用临时应用包、独立配置目录和合成 v4 草稿验证了写入链路。通过 LaunchServices 打开草稿后，应用仍在运行时，`settings.json` 中第一项颜色从 `[21, 43, 65]` 变为草稿中的 `[71, 82, 93]`，草稿文件字节一致。下次启动会应用新的全局值，由启动代码确定。若把「全局默认配色」和「当前草稿配色」定义为应彼此独立的结果，那么两者各自需要明确的写入来源。显示记忆的继承范围也需要单独明确。[启动加载偏好](../../src/app/state.rs#L280)、[应用偏好](../../src/app/state.rs#L313)

这组矩阵四格全为 `X`。交换顺序仍然有对角线上方的非零项。上一节的 7×7 将偏好固定，所以它仍可为下三角。

### 设置、退出与安装更新

FR12 的输出是在安装开始前取得已验签包。FR11 同时观察关闭批准和最后的窗口或进程状态。

| 功能需求 | DP9 配置保存与恢复 | DP12 检查与下载 | DP11 关闭协调 | DP13 重启安装 |
| --- | :---: | :---: | :---: | :---: |
| FR9 保存和恢复跨启动偏好 | X | 0 | **X** | 0 |
| FR12 获得已验证的更新包 | X | X | 0 | 0 |
| FR11 安全结束当前工作 | X | 0 | X | **X** |
| FR13 经用户确认完成更新安装与重启 | 0 | X | X | X |

- **偏好和关闭双向影响。** 关闭收尾主动捕获并保存最新偏好和布局（`A9,11`），保存结果又决定能否完成关闭（`A11,9`）。普通退出遇到设置故障可以等待用户明确放弃；更新重启遇到设置故障则拒绝开始安装。[关闭发起设置保存](../../src/app/lifecycle.rs#L310)、[布局快照](../../src/app/state.rs#L344)、[设置故障决策](../../src/app/lifecycle.rs#L72)
- **关闭和安装也有双向作用。** 安装需要关闭协调器通过未保存保护、收尾和复核（`A13,11`）。安装开始后，关闭命令被拦截，安装结果又决定退出旧进程还是恢复窗口（`A11,13`）。下载供给已验证的包（`A13,12`），自动检查开关影响下载流程（`A12,9`）。各项串过中间接口的影响只记在直接接口处。[更新设置路由](../../src/app/state.rs#L211)、[下载与安装交接](../../src/updates/mod.rs#L366)、[安装结果处理](../../src/app/lifecycle.rs#L174)、[安装期间关闭处理](../../src/app/lifecycle.rs#L276)

在把「当前工作安全收尾」「安装后的旧进程退出」一起计入 FR11 时，这个 `4×4` 矩阵每行至少有两个 `X`，因此任意行列重排都找不到只有一个 `X` 的首行。若只分析预安装阶段，可把「保存当前设置」「得到关闭批准」「执行安装」作为依次产生结果的独立阶段。这样得到的顺序适用于预安装切面，整个退出及更新交互仍包含等待、取消和恢复窗口。

系统打开也会与关闭协调交互。新外部打开会撤销未完成的退出意图；关闭或文件确认在进行时，队列又会等待，退出过程中迟到的打开结果会被丢弃。这在同一活动窗口中体现为 FR10 和 FR11 的双向作用。键盘、帮助和开场通过共用模态优先级接入同一层。诊断写入则消费各功能的失败摘要。[外部打开取消退出](../../src/app/files.rs#L58)、[等待条件](../../src/app/files.rs#L121)、[退出时处理打开结果](../../src/app/files.rs#L336)、[模态优先级](../../src/app/keyboard.rs#L7)、[后台诊断](../architecture.md#后台任务与关闭)

**扩展结论。** 把跨启动偏好、系统打开、关闭与更新纳入后，当前 FR/DP 划分下的完整模型包含双向耦合，矩阵无法通过成对重排成为下三角。除配色的 macOS 原生探针外，七项现有定向测试通过，覆盖配色编辑持久化、显示记忆、外部打开对退出的影响、更新取消及设置保存失败、开场重播和诊断。现有验证足以检查这些具体行为，缺少用于计算第二公理信息量的可比成功率。
