# 架构

## 工作区与依赖方向

项目仅面向桌面应用。`crates/zhiji_core` 是供桌面应用使用的排盘计算模块，输入为可能不完整的模拟参数，输出为命盘；`crates/zhiji_ui` 提供基于 Rune 的通用控件。两者均为内部模块。仓库根目录是桌面应用包，负责组合窗口、业务交互和绘制。

```text
Rune 事件 → app/view 与功能视图 → AppState（窗口、组合、生命周期）
                                  ├─ Workspace
                                  │  ├─ Session → zhiji_core、ChartView
                                  │  ├─ Marking（标注与历史）
                                  │  ├─ ColorEditor、InputEditor
                                  │  └─ 持久偏好、布局、临时交互状态
                                  ├─ document（文档身份、保存基线与文件操作）
                                  ├─ Tasks（图片导出、复制）、设置保存队列
                                  └─ updates、diagnostics（独立能力）

Workspace → ImageSnapshot → 导出与复制任务
          └→ DraftSnapshot → 草稿保存任务
功能视图 → zhiji_ui 通用控件；组合层绑定业务动作
```

`zhiji_core` 和 `zhiji_ui` 不依赖桌面应用，`zhiji_ui` 不依赖排盘领域。通用控件表达视觉及无障碍状态，业务事件和状态由应用绑定；字体由应用提供，名称与组件样式共享。`Session` 不依赖 Rune 控件、窗口或 GPU。界面从已有状态读取数据，不建立第二份排盘或标注文档。

`zhiji_ui` 采用受控组件接口，调用方提供状态并绑定操作。颜色选择器的像素尺寸、色彩面板、滑条与预览由 `zhiji_ui` 管理，飞化配色、颜色计算、文本输入和编辑事务由应用负责。确认对话框、菜单与图标按钮的通用外观也由 `zhiji_ui` 提供；文案与动作由应用组合。接口约定及示例见 [zhiji_ui 说明](../crates/zhiji_ui/README.md)。

外观、动效、默认取数方式、界面字号、界面简繁体、命盘简繁体、布局恢复、显示记忆、导出倍率、全局盘面配色、日期规则、窗口尺寸与位置属于工作区偏好，统一保存在用户配置目录的 `settings.json`，不写入草稿；旧版单值 `appearance` 文件和缺少 `chart_chinese_variant` 的统一简繁设置分别用于迁移。关闭颜色编辑器后，盘面配色变化写回同一文件。界面颜色由 `zhiji_ui::ColorToken` 的语义 token 成对定义浅色与夜间值，组件只接受 token；窗口视图构建时以线程局部作用域选择模式、界面用字和界面字号倍率，退出视图时恢复原状态。命盘绘制和图片导出另以命盘用字作用域生成标签，因此界面与命盘可以混用文案用字，而盘内控件名称和用户标注仍沿用界面语言。界面字号只缩放 `zhiji_ui::font` 创建的界面文字，命盘与标注保留既有尺寸。`i18n` 用 `ferrous-opencc`（Apache-2.0，纯 Rust）的 OpenCC 台湾繁体词典转换两类文案，并补充 OpenCC 未覆盖的台湾软件常用词；天干地支在转换前受保护，避免“丑”被当作“醜”，地点专名中的“乾”同样保持原字。用户输入、已有文件名及路径保持原样，程序生成的默认草稿名和导出名随界面用字转换；Rune 的全局语言标签由界面用字选择区域字形，命盘沿用该字形。导出和复制将命盘用字与界面语言随图片快照冻结。窗口帧从视图构建到帧编码结束持有语言门闩，离屏渲染只在视图构建和文字排版阶段临时固定语言并恢复窗口选择，避免前台重绘读取导出语言或污染后续字体状态。用户选择的标注和飞宫颜色作为运行时数据保留原值，深色标注在夜晚盘面绘制细描边以提高可读性。`tools/verify.mjs` 禁止 token 定义文件之外的生产 Rust 文件出现十六进制颜色字面量。

### 日期计算包

独立 Rust 历法包 `crates/zhiji_calendar` 提供基础类型、固定 `tyme4rs` 的公农历适配、IANA 时区解析、真太阳时近似计算和干支反推，由 App 的日期取数调用。接口与限制见[包说明](../crates/zhiji_calendar/README.md)。包内模块按职责划分：

| 包内模块 | 职责 |
| --- | --- |
| `solar_time` | 根据已解析的时刻与经度计算真太阳时及跨日结果，保留原始时刻与校正结果的区别 |
| `ganzhi_reverse` | 根据四柱、查询范围及明确的计算口径搜索候选时间区间，处理搜索边界并正向复核候选 |
| `timezone` | 将 IANA 地点时区和民用钟表时间解析为唯一、重复或不存在的时刻，保留实际 UTC 偏移 |

`zhiji_calendar` 不依赖桌面状态、Rune、`zhiji_ui` 或 `zhiji_core`，也不承担命盘绘制与文件操作。App 负责出生地与输入解释、调用历法包及回填现有排盘参数；`zhiji_core` 继续负责手动排盘参数到命盘的计算。历法适配显式区分两种公历口径，检查已知历史异常、非标准月长与转换端点；真太阳时与干支反推分别自行实现，不把历法库的内置四柱反查作为反推模块实现。

## 状态与事务

`AppState` 是 Rune 的窗口根状态，分别持有 `Workspace`、`document`、图片任务组、窗口句柄和唤醒器。`document` 的 `DraftState` 包含当前文档路径、磁盘指纹、保存基线及文件操作，不归入短期图片任务；其内容仍由 `Workspace` 拥有，通过独立快照协作。`Workspace` 私有持有 `Session`、`Marking`、颜色编辑器及日期编辑器，通过操作维护这些状态。排盘动作经 `Workspace::apply` 先提交文字和颜色编辑，再进入 `Session::apply`；有效输入变化时重算命盘并刷新联动，纯显示开关更新显示状态。具体联动见[领域规则](domain.md)。

工作区的 `WorkspacePreferences` 持有跨文档沿用的偏好，`WorkspaceLayout` 只持有单双列和侧栏布局，`WorkspaceUi` 只持有当前交互和呈现状态。三者不复制 `Session` 数据，偏好默认值仍来自 `PreferenceValues`。应用视图通过 `WorkspacePresentation` 读取少量布局和交互信息，通过工作区动作提交改变；不开放内部字段的写权限。替换文档沿用偏好与布局，并按既有规则关闭设置面板。

macOS 文档打开由 `platform/documents.rs` 在应用启动阶段接收，只将拥有所有权的路径投递到 Rune 主线程更新，不持有业务状态。`app/files.rs` 串行协调外部请求、当前文件操作与未保存确认；文件内容读取和校验仍属于 `draft` 后台任务。系统入口的参数错误等待当前任务完成后展示，避免被无关保存成功覆盖。

`app/view` 是应用根视图，负责窗口、工作区、标题栏、菜单、反馈和弹层的组合；`workspace/view` 只提供可由不同宿主复用的排盘控件、命盘交互及日期编辑绑定，生产代码不依赖 `AppState`。标注工具栏和菜单、草稿与导出控件通过只读状态和动作回调接入；排盘控件、命盘拖动和文字输入通过 `WorkspaceHost` 接入，实现该宿主的类型同时取得一致的 `InputEditorHost` 绑定。设置视图通过 `PreferencesHost` 取得小值只读投影 `PreferenceValues` 并提交 `PreferenceChange`；加载、恢复默认和用户操作复用同一个处理入口，保存从同一投影生成。颜色编辑和关于页分别依赖 `ColorEditorHost`、`AboutHost`；关于页读取独立更新器的状态及 `DiagnosticStatus`，通过宿主请求反馈链接等应用行为，不引用 `app` 的实现。投影不持有第二份可变领域状态，盘面配色和显示仍属于 `Session`，日期规则属于日期编辑器，更新调度属于更新器；文件通过 serde flatten 保持原有扁平 JSON。

设置入口位于标题栏右侧，在右侧工作面板内切换排盘信息与设置页面；设置页返回按钮位于右侧面板顶部左端。设置分为常规、外观、排盘和关于四类：常规管理导出倍率、布局恢复和恢复默认；外观管理界面外观、动态效果、界面字号、界面简繁体、命盘简繁体和全局盘面配色；排盘管理默认取数方式、晚子时生日、四柱日柱换日和显示记忆；关于展示版本、配置目录和许可证。窗口尺寸、位置、单双列和侧栏状态只在关闭时写回布局偏好，下次启动按恢复开关应用；恢复默认的范围见[界面规范](interface.md)。`WorkspaceHost` 的只读和可变访问器必须指向同一工作区。应用根状态在组合层实现这些接口，功能视图不直接依赖 `AppState`。Rune 的事件仍由根状态接收；这些接口不代表已经实现多页面或多窗口，多工作区切换时还需确定事件对应的工作区身份。

退出临时编辑、发起导出或保存草稿时，工作区和应用状态协调颜色提交、文字提交和标注面板关闭，保持各操作原有的顺序。生命周期协调只访问所需的关闭状态；跨功能菜单、反馈和导出控件由应用根视图组合。

排盘输入的日期编辑状态由工作区持有，与生效的 `Session` 输入分离；打开时读取当前性别，日期和地区选择在确认前不产生排盘写入。编辑、时区确认、重复时刻确认和反推候选四个步骤互斥，候选列表与选中项共同归属于候选步骤；返回按钮和 Escape 共用确认步骤的退出逻辑。关闭后保留日期与地点选择，再次打开时刷新性别；这些临时选择不进入草稿文件。日期、列表、级联、搜索、图例和弹窗展示组件由 `zhiji_ui` 提供，`InputEditorHost` 将编辑状态和一次性应用结果的动作绑定到视图。

`input/mod.rs` 只组合模块和宿主绑定；`input/editor.rs` 与 `input/view/` 为同级模块。确认步骤、已选时区、重复时刻及最近解析结果由编辑器私有持有，视图只借用步骤并调用校验后的选择操作；错误步骤、越界候选或不属于当前提示的时区与时刻不改变已有选择和反馈。表单草稿及局部界面状态仍在输入模块内编辑，不与确认流程混为第二份状态。提交按公历、农历、四柱分别处理，查询发起与完成核验共用唯一反推请求构造。

公历、农历和干支是取得排盘参数的输入方式；`zhiji_calendar` 接收明确输入和规则并返回结果或错误，不直接修改会话。桌面应用的 `input/calculation.rs` 负责紫微取数规则、五行局和紫微位置。干支候选须经用户选择，工作区随后协调 `Session::apply_date_input` 一次性更新参数和命盘；失败或取消不改变当前命盘。四柱反推在独立线程执行，每个编辑器最多保留一个执行任务和一个最新待执行请求。输入、年份组、反推规则或面板状态变化同时推进世代并取消旧计算；旧线程退出并回收后才启动最新请求。历法包在每日筛选与逐秒计算间检查取消，不返回部分候选。完成结果仍须匹配当前请求才能写回编辑器，销毁编辑器也会发出取消。显示、配色、标注及已有后台任务保留。草稿格式不增加出生数据。

标注的更多菜单和右键菜单由工作区管理同一互斥状态。日期取数打开时独占工作区键盘，Escape 先关闭子弹层、再关闭主弹窗。其余情况下，窗口路由先关闭标注菜单、再取消待确认草稿操作，随后由工作区处理应用菜单、颜色、设置、文字和选择；撤销重做及标注键盘操作也由工作区处理。

屏幕通过 `Session::view` 借用数据。`Workspace::capture_export_image` 结束颜色和文字编辑后冻结图片；`Workspace::capture_copy_image` 提交文字并关闭标注面板，同时保留颜色编辑器的原有状态。两者将 `ChartSnapshot` 与可见标注组合成拥有数据的 `ImageSnapshot`，交给对应任务。图片任务只读取快照；系统保存对话框打开后继续编辑，不改变已发起的导出内容。

`Workspace::capture_draft` 结束临时编辑，并在保存对话框出现前冻结草稿数据，包含全部标注及其可见性，即使标注当前隐藏也会保存。草稿模块在后台完成读取和校验；恢复入口要求已校验的标注，并检查干支配对和飞宫星曜，再准备工作区恢复内容。替换确认后，工作区一次性安装命盘和标注。保存的飞宫值在读取时保持原样。标注数据的几何和数量约束由标注模块校验，草稿模块负责版本及文件语义；保存前也检查这些约束，避免写出不能重新打开的草稿。

`draft` 持有当前路径、磁盘内容指纹和最后成功保存的快照。未保存状态比较现有工作区内容与快照，恢复原值后回到干净状态；尚未提交的文字标注也计入修改。文件名和路径仅在成功保存或安装已校验草稿后更新。`app/files.rs` 协调未保存选择及保存后的打开／退出动作；保存期间的新内容不能被旧快照的成功结果清除。退出收尾还会比较用户确认时的快照，防止等待其他后台任务时发生的新修改绕过提示。最近文件位于配置目录的 `recent-files.json`，后台按顺序写入并合并后续更新，不存储盘面内容。

标注编辑由单一 `Marking` 状态管理。近期撤销与重做记录分别保留约 16 MiB 载荷，较早记录转存匿名临时文件；转存失败时保留内存记录。旧记录按需在后台读取、校验和解码，每条历史只允许一个在途读取，不主动预取大记录。完成并匹配栈版本后才能推进历史位置；新编辑或清空作废旧结果并协作取消读取。等待时暂不接受重复撤销/重做，其他编辑可以继续并取消未应用的历史操作。历史不写入草稿。

## 后台任务与关闭

`preferences::persistence` 持有设置保存队列：UI 只冻结快照，JSON 编码与临时文件替换在后台执行。一次只写一个版本，期间变化合并为一个最新待写版本；旧任务结果不覆盖新版本状态。配色自动保存比较已提交快照，失败不会逐帧重试；下一次设置操作或关闭可以重试。正常关闭等待全部已接受设置写入，更新安装还要求最新写入成功。与草稿一样，持久化任务不按图片任务的两秒宽限期丢弃；强制终止不受该协议保障。

设置读取限制为 64 KiB，缺失、不可读、超限和内容损坏分别返回。只有缺失走首次启动及旧外观迁移；其他故障采用临时默认值并禁止自动覆盖，自动更新临时关闭，避免在未知用户偏好时发起网络操作。用户明确恢复后，在后台先将原文件流式复制到同目录唯一命名的 `settings-recovery-*.json`，备份失败不替换原文件，再提交当前设置；用户也可修复原文件后重新读取。普通关闭遇到设置失败会重新显示窗口，普通退出提供继续使用、重试或明确放弃设置退出；放弃设置不绕过草稿批准快照复核。更新安装不能放弃设置保存。

`task::Task` 保留线程句柄，捕获业务闭包异常并唤醒宿主，只回收已退出线程。取消是协作信号，不等同于线程已经退出。设置写入完成既有原子替换，反推主动响应取消；两者的调度和结果提交分别由所属模块管理。因为完成唤醒可能早于线程彻底退出，根状态在执行槽非空时安排短间隔轮询，不在 UI 上执行阻塞等待。

`app::help` 编译时内嵌 `docs/user-guide.md`，从同一来源呈现正文及当前平台快捷键，不依赖网络、运行时文件或 WebView。根状态持有当前帮助页，模态打开期间拦截工作区命令，关闭后恢复焦点；系统帮助菜单与关于页共用入口。

`updates` 是三端唯一的更新状态机，持有自动调度、一个在途任务、取消标记、下载进度和已验签包；`app::updates` 只绑定应用操作、重启保护和窗口通知。自动偏好保存在 `settings.json`；无头工具不启动更新器。`updates::transport` 通过有界 HTTPS 读取当前平台及架构的签名元数据，先验签后解析，正式版本、目标、URL、包大小及包签名均受元数据签名约束。下载按实际字节限制在 256 MiB，元数据限制 128 KiB；关闭或取消丢弃接收端并通知任务停止，迟到结果不能覆盖新任务。元数据界面截止 30 秒、下载截止 300 秒，安装不使用可丢弃超时。只发送固定请求头和版本，不发送文档、路径或系统信息。

`platform::update_install` 适配 cargo-packager-updater 的应用包及 AppImage 安装，Windows 直接执行已验签 NSIS，避免经 shell 转义路径。Unix 安装库只处理临时副本，验证后在目标同文件系统原子交换新旧路径；额外备份用于普通失败及异常回滚，不支持原子交换的文件系统不退回到删除旧版。macOS 解压前检查路径、文件类型、数量、总大小、应用标识及版本。重启使用独立 `Update` 文件意图，经未保存决策、设置保存和后台收尾后才启动安装；安装期间阻止编辑，成功后退出旧进程。Unix 新进程先等待旧进程释放单实例锁，Windows 沿用 NSIS 的重启参数。Linux DEB 和开发裸二进制不覆盖安装文件。

`diagnostics` 负责默认诊断日志和目录打开任务，不依赖 `app`。正常桌面初始化后才启用自动记录；调用方只提供脱敏摘要，日志在后台以非阻塞文件锁协调写入并轮换。导出模块继续拥有错误分类和详细诊断，只将安全摘要交给默认日志。诊断目录任务在发起时冻结路径，只持有结果通道及唤醒能力，不持有工作区；完成后经根状态统一轮询更新设置页。设置页只取得目录、忙碌状态和错误的借用投影，不持有诊断任务对象。该任务不写草稿，不阻止应用退出，目录请求成功仅表示系统接受调用。

panic hook 的固定脱敏标记例外地在异常线程同步尽力写入，以便线程或进程结束前有机会落盘；仍使用非阻塞文件锁，不读取异常载荷，并保留原 hook。关于页文本复制反馈只持有最近的入口和到期时间，通过统一轮询移除，不持有剪贴板内容。

Windows/Linux 的 `platform::instance` 使用配置目录内的文件锁选出唯一实例，以本机回环 TCP 和随机凭据转发激活或文件打开请求。入口先把相对路径转换成发起进程的绝对路径，传输保留 Unix 原始字节或 Windows UTF-16。监听线程只向 `AppHandle` 提交更新，主线程领取请求后才确认；超时则原子取消尚未领取的请求，迟到闭包不再执行。此确认不代表草稿已读取成功，读取失败仍由应用反馈。请求有大小、数量及整体读取期限限制，退出可取消未完成连接。协调失败显示系统错误并退出本次启动，不创建无锁的第二个工作区。无头工具绕过实例协调。`fs2`（MIT/Apache-2.0）封装平台锁，`getrandom`（MIT/Apache-2.0）取得系统随机凭据；不进入领域核心。

后台工作只持有操作所需的快照或文件路径、结果通道及唤醒能力，不持有 `Tx` 或可变应用状态。一次聚合轮询执行所有任务，不能用布尔短路跳过后续轮询。

文件提交使用目标目录的临时文件。首次保存和另存为默认不覆盖既有目标；直接保存先核对已知内容指纹，外部修改或删除时等待用户确认。符号链接保存到其解析目标，保留链接本身。确认授权替换所选路径，不锁定其他进程对该路径的修改，也不保证核对与提交之间其他进程不会再次写入。

关闭窗口时等待正在写入的草稿。图片任务按当前生命周期规则取消或等待约两秒到达安全点；复制反馈、草稿保存失败或待确认覆盖可能使窗口重新显示。macOS 收尾后隐藏窗口并保留会话，Dock 重开沿用 Rune 的恢复行为；明确退出才结束进程，菜单、快捷键及 AppKit 的退出请求共用该流程。启动布局通过单窗口工厂的创建参数恢复，不注册持续定位约束；用户移动或缩放后，菜单命令、文件反馈及窗口重新显示均不重新套用启动矩形。窗口管理器仍可能在显示窗口或显示环境变化时调整位置。Windows/Linux 关闭窗口仍退出。强制终止和系统崩溃不受正常关闭协议保障。

## 资源

资源属于 `assets/`，生成工具属于 `tools/`。构建使用已生成资源，生成脚本不进入应用启动流程。

资源修改须同步审阅来源、许可、嵌入路径、`assets/manifest.json` 和打包清单。字体族名称、语言、字形覆盖和视觉基准属于行为约定；变更须同步更新测试与相关说明。具体来源见[字体](../assets/fonts/README.md)与[图标](../assets/icons/README.md)说明。

## 首次启动呈现
设置中的重播复用 `app::launch`，以无持久化标记的新时间轴启动后台资源准备，不替换工作区状态。重播与首次播放使用相同的模态、跳过与资源释放流程。
`app::launch` 拥有首次运行记录、单调时间轴及模态呈现。`artwork` 在一次后台任务中生成星云纹理并从既有 App 图标提取透明主体，`paint` 使用 Rune 原生图形和纹理绘制；不引入 WebView、视频或网页运行时。完成后释放纹理并停止申请动画帧。命盘目标位置读取真实布局，不使用工作区截图。领域计算与通用控件不依赖开场状态。
普通离屏工具不读取或写入首次运行记录。`visual-test` 下的 `launch-*` 场景独立覆盖开场关键帧，`launch-play` 提供完整可重现时间轴，均不写用户配置。
