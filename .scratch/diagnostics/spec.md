# 本地诊断入口

本轮增加诊断入口和手动“查看更新”入口；自动版本检查、下载安装、签名与系统交互验收继续单独处理。

- 默认在配置目录的 `diagnostics/` 下保留当前 `zhiji.log` 和上一份 `zhiji.previous.log`，各不超过 512 KiB，单条摘要有界。写入不阻塞 UI，竞争或写入失败尽力记录，不改变业务操作结果。
- 记录启动版本、操作系统和执行架构，以及导出失败阶段／错误类别、草稿打开或保存失败、设置保存失败。自动日志不记录文件路径、命盘输入、异常载荷或用户内容。
- 原有 `ZHIJI_DIAGNOSTICS` 详细导出日志保持额外输出，仍由用户显式指定。
- “设置 → 关于”的本地维护组提供诊断日志操作：打开目录、复制目录；使用三平台系统文件管理器，不经过 shell。创建目录和启动器放在后台，防止重复点击，错误可见且保留复制路径的恢复操作。
- 应用信息区的“查看更新”打开项目版本发布页，不自动检查或下载安装。更新与目录打开使用无边框文字操作；帮助、反馈和重播使用整行入口。字号、40 点行高、10 点左右内边距及颜色沿用其他设置页，不使用大标题。
- 构造状态和离屏展示不创建目录；无头工具不写启动日志。沿用项目布局和参考图，只有相应卡片区域可变化。
- 验证临时文件追加、轮换、故障、竞争、默认摘要脱敏、异步打开状态及复制路径；完成 Rust、GPU、跨目标检查。用户已跳过的平台安装与真实桌面验收不在本轮重新执行。
