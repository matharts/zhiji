# 复制请求反馈与异常诊断

- 关于页的“复制版本与系统信息”“复制诊断目录”在图标附近显示三秒提示“已复制”，命盘图片复制使用同一文案。界面不暴露请求分发状态；当前接口仍不回传系统剪贴板写入结果。重复操作只显示最近一次的提示，禁用入口不触发提示；提示不占用布局、不遮挡触发图标，并支持无障碍状态。
- 正常桌面启用诊断时安装一次 panic hook：沿用非阻塞文件锁和日志轮换，在 hook 同步尽力写入固定脱敏标记及主线程／其他线程分类，然后调用此前 hook。无头模式及常规测试不启用。日志不读取 panic 载荷、线程名、源码路径、配置目录或其他用户数据。
- Rust panic hook 也会收到随后被捕获的 panic；记录 `rust panic observed`，不把标记解释为进程已崩溃。不可捕获的系统故障、强制退出和写入失败不保证被记录；stderr 保持原有 hook 行为。
- 检查默认／深色／大字号和小窗口的两处短暂反馈及对应剪贴板请求；通过隔离子进程核验真实 panic 落盘、载荷和路径脱敏、原 hook、捕获后继续、目录错误及文件锁竞争。运行 Rust、GPU、跨目标检查，不修改草稿。
