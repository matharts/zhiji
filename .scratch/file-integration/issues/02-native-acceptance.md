# 前台验证文件打开与窗口恢复

## 已有证据

- 真实包内含 `.ziwei` 类型声明、Editor 角色与图标资源。
- 使用独立 Bundle ID、用户 Applications 下的测试副本、临时配置及合成草稿，通过 LaunchServices 的运行中检查曾依次到达：冷启动载入、类型识别、打开方式发现、热打开同一实例、重复打开保留编辑、未保存取消及保存、损坏文件反馈及内容保留、关闭后重开。
- 原生菜单检查通过。上述分段观察不等于 `tests/macos_file_open.swift` 整套通过；最终版本仍需要重跑。
- 开始时冷启动丢失文件事件，已通过 WillFinishLaunching 阶段重注册修正；其后的冷启动检查已到达文档窗口。
- 取消最小化、隐藏及前置补齐了 Rune 普通 Open 与 Dock reopen 的路径差异；源码审查通过，实际窗口结果待确认。

## 阻断

当前台前调度环境经常只暴露 125×117 的应用缩略图，AX 列表可能为空；即使进程报告 active，也无法稳定取得可见主窗口。原生脚本曾分别在窗口关闭、最小化准备以及后续重跑的修改标记等待失败。没有将这些失败记为通过，也未放宽窗口恢复断言。

另尝试直接操作 Finder：按 bundle ID 可以读取“下载”窗口的无障碍树，但发出前往文件夹操作及读取截图均返回 `cgWindowNotFound`，未完成 Finder 实际双击检查。暂时性的鼠标点选缩略图尝试未能建立可靠验证，已从测试脚本移除。

## 待验收

先保存现有工作，退出旧实例后使用最新 `target/release/知几.app`。仅使用合成草稿：

1. Finder 双击草稿冷启动，确认文件名、内容与图标；“打开方式”可列出知几。
2. 应用运行中打开另一份草稿，确认没有第二个实例；有未保存编辑时分别验证取消、保存、不保存。
3. 分别关闭窗口、最小化、隐藏应用，再从 Finder 打开文件，确认窗口完整显示并处于前台。
4. 打开损坏文件，确认当前文档及未保存修改保留，错误反馈可见。

也可在可交互的桌面前台按 `docs/testing.md` 运行原生脚本。Windows/Linux 已纳入本轮，文件关联、单实例转发与剩余验收见 `03-windows-linux.md`；本任务只记录 macOS 原生验收。
