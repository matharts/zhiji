# 文件系统集成

Status: ready-for-agent
Progress: claimed

## 范围

为 macOS、Windows 和 Linux 的打包应用注册 `.ziwei` 文档类型、名称及图标，接入系统文件管理器和“打开方式”的外部打开请求。启动、运行中、隐藏、最小化和关闭窗口后的行为遵循各平台窗口生命周期，打开到当前单工作区，复用标准文件体验的验证及未保存保护。不改变草稿格式、命盘绘制或引入多窗口。

## 行为

- 冷启动不丢失系统打开事件；从文件启动直接进入文档，跳过开场动画。
- 已运行时恢复并激活当前窗口。再次打开当前路径仅唤起，保留尚未保存的编辑。
- 外部文件在后台读取并完成格式校验后，才允许替换当前文档；失败显示反馈并保留内容和路径。
- 未保存的当前文档仍提供保存、不保存、取消；保存失败或保存期间有新修改时不替换。
- 文件操作或日期弹窗进行中，外部请求排队，待当前交互完成后处理；取消本次打开不会替换文档。连续重复请求去重，队列有界。
- 收到多个文件的批次时明确提示一次只能打开一份，不隐式选取最后一份。Windows Shell 采用原生 `MultiSelectModel=Single`，多选时不提供打开动作，避免 Shell 拆成多次独立启动；命令行传入多路径仍提示。
- 新的外部打开请求取消尚未完成的退出意图，但不取消在途保存；仍经未保存保护。
- 仅声明文档处理能力，不主动更改用户已选择的默认打开应用。

## 验收边界

沿用上一轮已确认的三层边界：应用 Runtime 验证外部请求与保存/取消/排队交错；真实临时文件验证损坏文件与读写结果；各平台打包应用分别验证类型声明、图标资源、系统冷/热打开、窗口恢复和当前文档保护。自动化事件验收与文件管理器人工双击观察分别记录，不以一项代替另一项。
